# Research Evidence Explorer V1

Research Evidence Explorer is a local, single-user workspace for **abstract-level**
literature review. It helps a researcher record a search, screen papers, inspect
source-stated limitations or future-work directions, and export a report. Its
candidate directions are not declarations that a topic is unstudied.

## Problem and outcome

Early literature reviews often spread queries, paper lists, screening decisions,
and notes across separate files. That makes it difficult to explain why a paper was
included or where a proposed research direction came from. V1 keeps those steps
together and makes accepted directions traceable to an exact abstract sentence.
The intended first users are students and researchers preparing a scoped review.
Whether it saves them time or improves review quality still needs user evaluation.

## Run

From the repository root, install `requirements-v1.txt` in the project virtual environment
and run:

```powershell
.\.venv\Scripts\python.exe -m streamlit run research_app.py --server.address 127.0.0.1
```

The application stores its SQLite database at `data/research_evidence.sqlite3` by
default. Set `REE_DB_PATH` before launch to use another location. The database is
ignored by Git; back it up if you want to retain review decisions. Set
`OPENALEX_API_KEY` if your OpenAlex access requires a key. The key is sent only to
OpenAlex and is not written into the search log.
V1 has no user accounts, so run it locally with the address shown above.

## First review

1. Create a project in the sidebar with a focused question and explicit inclusion and
   exclusion criteria.
2. Run an OpenAlex title/abstract search or import a CSV with `title` and `abstract`
   columns. The bundled AI-in-education CSV is available for an offline walkthrough.
3. Open **Screen papers**. Mark each paper `include`, `exclude` (with a reason), or
   `unsure`. Only included papers are used to discover directions.
4. Open **Investigate directions** and click **Find directions in included papers**.
   Each direction is an exact sentence from an abstract with a character offset.
5. Read related included papers and search for counterevidence. Record the review in
   a note. Acceptance requires marking the counterevidence check as done.
6. Download the Markdown report. It lists search history, screening totals,
   exclusions, and accepted directions with their sources and reviewer notes.

Searches store the query, filters, date, result counts, and imported paper records.
Re-running the same search links the run to existing papers without duplicating the
same DOI. Failed OpenAlex requests remain visible in the search history.

## V1 pipeline

```text
question and criteria
    -> saved OpenAlex search or CSV import
    -> paper identity and deduplication
    -> human title/abstract screening
    -> exact limitation/future-work sentence extraction
    -> similar included abstracts for inspection
    -> human counterevidence check and decision
    -> saved search history and Markdown report
```

V1 has no automatic claim that a gap exists. Related abstracts are retrieval leads,
not automatically classified as support or contradiction. The current cue-based
extractor can miss directions or flag an irrelevant sentence. Full-text PDF parsing,
multiple reviewers, account access, report versions, and a labeled research-quality
evaluation set are later milestones. OpenAlex searches in V1 are limited to article
titles and abstracts; some relevant work may be outside that scope.

## Verify

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_workspace_v1.py
```

The V1 tests exercise search pagination with a mocked API response, CSV validation,
persistent screening and review decisions, deduplication, source offsets, and the
acceptance gate. They are software checks; they do not establish scientific recall
or the usefulness of the suggested directions.
